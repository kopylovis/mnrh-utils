# mnrh-utils

Набор утилит для обслуживания Mac. Одна команда `mnrh`, подкоманды — отдельные файлы.

Просто `mnrh` в терминале открывает меню: команды по группам, стрелки, поиск набором
(можно в русской раскладке: «ыыр» найдёт ssh), Enter — действия команды. Выбранное
запускается, а полная команда печатается, чтобы в следующий раз набрать её сразу.
`mnrh help` — список по группам, `mnrh help -a` — с описаниями. Группы, описания и действия
меню — в `share/mnrh/commands.tsv`.

mnrh claude           выбрать проект и запустить в нём Claude Code
mnrh claude root      запустить в домашнем каталоге
mnrh claude kcalm     сразу в проекте (достаточно начала имени)
mnrh claude sessions  сохранённые сессии с размером: продолжить, перенести в другую папку, удалить
mnrh claude sessions clean   битые ссылки, пустые сессии, папки удалённых проектов
mnrh claude sessions search fastlane подпис   поиск по всем прошлым сессиям (-p проект, -d дней)
mnrh claude sessions show <id> [N]            прочитать сессию с сообщения N
mnrh claude setup     поставить /restart, /forget, MCP-сервер mnrh, хук zsh и хуки Claude (--remove убрать)
mnrh claude restart   изнутри Claude: закрыть, claude update, открыть эту же сессию снова
mnrh claude forget    изнутри Claude: удалить эту сессию без следа и открыть чистую

mnrh disk --apply     удалить безопасное (спросит подтверждение; -y без вопроса)

mnrh repos --fetch    то же со свежими данными со всех remote

mnrh scroll on        переворачивать прокрутку мыши, не трогая трекпад (вместо Scroll Reverser)

mnrh sleep            что не даёт Mac уснуть, последние засыпания и пробуждения

                      битые ярлыки, лишние копии git/java/python/node/go, сломанный MacPorts

Короткие псевдонимы: `mnrh mem`, `mnrh kd`.

## Установка

### Через Homebrew

Одной командой:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/kopylovis/homebrew-tap/main/install.sh)
```

Скрипт ставит Homebrew, если его нет, затем `brew install kopylovis/tap/mnrh` и
`mnrh init`. Запускать можно повторно: сделанное пропускается.

Вручную:

```bash
brew install kopylovis/tap/mnrh
mnrh init
```

`mnrh init` спрашивает, где лежат проекты (по умолчанию `~/Developer`; предлагает найденные
`~/Projects`, `~/AndroidStudioProjects` и т. п. с числом git-репозиториев), сохраняет это в
`~/.config/mnrh/config` и предлагает `mnrh claude setup`. Без настройки и без `~/Developer`
`mnrh claude` сам спросит папку при первом запуске. `mnrh init ~/Projects` задаёт папку сразу,
`MNRH_PROJECTS=<папка>` переопределяет её на время.

`mnrh claude setup` кладёт команды `/restart` и `/forget`, хук zsh и регистрирует MCP-сервер `mnrh` в Claude Code.
Обновление: `brew upgrade mnrh`. Удаление: `brew uninstall mnrh`.

### Из исходников, для разработки

```bash
git clone https://github.com/kopylovis/mnrh-utils ~/Developer/mnrh-utils
cd ~/Developer/mnrh-utils
make install
mnrh claude setup
```

`make install` кладёт в `~/.local/bin` символическую ссылку на проект, поэтому правки
работают без переустановки. Другой каталог: `make install PREFIX=/usr/local`.
Если `mnrh` не находится, добавьте `~/.local/bin` в `PATH` в `~/.zshrc`.

Удаление: `make uninstall`. Проверки: `make test`.

### Выпуск новой версии

1. Поднять номер в `VERSION`, закоммитить и запушить.
2. Поставить тег: `git tag v$(cat VERSION) && git push origin v$(cat VERSION)`.
3. В `kopylovis/homebrew-tap` в `Formula/mnrh.rb` обновить `tag:` и `revision:` (полный хеш
   коммита с тегом: `git rev-parse v$(cat VERSION)^{commit}`). Версию Homebrew берёт из тега.

## Требования

macOS, bash и `/usr/bin/python3` из Xcode Command Line Tools
(`xcode-select --install`). От Homebrew утилита не зависит.

## Как работает `mnrh claude`

Показывает каталоги папки проектов (`mnrh init`, по умолчанию `~/Developer`) с текущей веткой и датой последнего коммита.
Выбор стрелками ↑↓ и Enter. Цифра сразу ставит курсор на пункт (`0` — домашний
каталог, `1` и `0` подряд — десятый), буквы фильтруют список по имени, Esc
сбрасывает фильтр или выходит.

Если у проекта есть сохранённые сессии, дальше предлагается продолжить одну из них или
начать новую (Enter — новая). Сессии свежие сверху: когда, размер, число сообщений и
название. Пустые (только `/clear` и т. п.) не показываются, открытые в других окнах тоже,
чтобы две копии Claude не писали в один файл. Шага нет с `--new` и когда после `--` уже
есть `--continue`, `--resume`, `--session-id` или `--print`; `open_claude` передаёт `--new`.

Затем так же выбирается режим:

- **caffeinate** (Enter) — `caffeinate -is`: Mac не засыпает ни от простоя, ни на
  питании от сети, пока идёт сессия. Экран гаснуть может. Нужно для долгих задач
  и для Remote Control с телефона — уснувший Mac обрывает сессию.
- **обычная** — просто `claude`.

`-k` и `-n` выбирают режим без вопроса, всё после `--` передаётся claude:
`mnrh claude kcalm -k -- --continue`. Закрытая крышка на батарее Mac всё равно
усыпит — caffeinate это не отменяет.

## Как работает `mnrh claude sessions`

Claude Code хранит сессии в `~/.claude/projects/<путь-папки>/<id>.jsonl`, рядом папка
`<id>/` с субагентами и большими выводами инструментов. `claude --resume` видит только
сессии текущей папки, поэтому после переезда проекта старые сессии пропадают из списка.

Без аргументов — список всех сессий, свежие сверху: когда, размер, папка, название
(своё из `/rename`, иначе придуманное Claude, иначе последний запрос). `● открыта` —
сессия идёт в другом окне, её не трогаем. Выбрал стрелками — дальше продолжить
(caffeinate или обычная), перенести или удалить.

- `mv <id> <папка>` — переносит файлы в хранилище новой папки и переписывает `cwd`
  внутри сессии, в том числе у субагентов. Остальное в файле не меняется, дата тоже.
- `rm <id>...` — удаляет сессию вместе с её `file-history` и строками в `history.jsonl`.
- `clean` — битые симлинки, сессии, где Claude так ни разу и не ответил, и папки
  проектов, которых больше нет на диске (вместе с их `memory`). Каждая группа
  спрашивается отдельно.
- `-l` — просто список с id, без меню.
- `search <слова>` — поиск по всем сессиям всех проектов (подробно ниже), `show <id> [N]` —
  прочитать сессию с сообщения `N`, `-10` — последние десять.

## Сжатие старых сессий: `mnrh claude sessions slim`

Большая сессия почти целиком состоит из скриншотов и выводов инструментов: у authmeister
из 481 МБ ~330 МБ занимают картинки (каждая хранится дважды — для модели и копия для
экрана), а текст разговора — несколько мегабайт. После `/compact` Claude Code отправляет
модели только сводку, сообщения, которые `/compact` сохранил (`preservedMessages`), и то,
что было после границы: при продолжении сессии он идёт от последнего сообщения назад и
останавливается на `compact_boundary`. Старая часть нужна только для прокрутки вверх, но
`--resume` всё равно разбирает весь файл — отсюда медленное открытие и память.

`slim` в части до двух последних `/compact` (`--keep N`) заменяет скриншоты подписью
`[скриншот 1,2 МБ удалён: mnrh slim]` (в копии для экрана — картинкой 1×1, чтобы экран не
ломался) и обрезает выводы длиннее 8000 символов до начала и конца. Не трогает: всё после
этой границы, сообщения, сохранённые при `/compact`, цепочку до последнего сообщения,
сообщения Claude (в них подписи блоков размышлений) и историю файлов для `/rewind`.

Перед записью сжатый файл сверяется с оригиналом: число строк, `uuid`, `parentUuid`,
типы и время совпадают, всё, что попадает в контекст модели, совпадает побайтно, иначе
ничего не записывается. Оригинал сжимается в `~/.cache/mnrh/slim-backup/` и хранится
14 дней; `slim <id> --undo` возвращает его вместе с сообщениями, дописанными после
сжатия. Дата сессии не меняется. Открытые сессии не сжимаются.

```
mnrh claude sessions slim              что можно освободить по всем закрытым сессиям
mnrh claude sessions slim <id> --copy  сжатая копия с новым id — открыть и проверить
mnrh claude sessions slim <id>         сжать (спросит подтверждение, -y без вопроса)
mnrh claude sessions slim <id> --undo  вернуть оригинал
```

Чего не будет после сжатия: старых скриншотов при прокрутке вверх, а при `/rewind` в
точку до этих двух `/compact` — картинок и полных длинных выводов в том старом разговоре.

## Поиск по прошлым сессиям

Тот же поиск доступен Claude как MCP-инструменты `session_search` и `session_read`: можно
спросить «как мы в sightra настраивали подпись для RuStore?», и Claude сам найдёт это в
прошлых сессиях и прочитает нужное место. Ищется текст запросов, ответов Claude, выполненные
команды (`$ …`, для остальных инструментов — файл или шаблон) и сводки после `/compact`.
Выводы инструментов и служебные сообщения не индексируются. Все слова должны встретиться в
одном сообщении, регистр не важен, слово ищется как подстрока, поэтому лучше давать основу:
`подпис`, а не `подписью`. Фраза — в кавычках. Текущая сессия в поиск не попадает.

Индекс лежит в `~/.cache/mnrh/sessions-index/<id>.json`: из сессии берётся только текст
(у самой большой из 481 МБ получается около 1 МБ). Первый проход по всем сессиям занимает
пару секунд, дальше дочитываются только новые строки, и запрос выполняется за доли секунды.
Индекс обновляется в фоне при старте каждой сессии (хук `SessionStart`). У удалённых сессий,
в том числе через `/forget` и `sessions rm`, индекс удаляется сразу.

## Устаревшие зависимости: `mnrh deps`

Разбирает `gradle/libs.versions.toml` (версии, библиотеки, плагины), сверяет с Google Maven,
Maven Central и Gradle Plugin Portal и показывает, что обновилось, насколько (мажорная,
минорная, патч) и какие библиотеки на этой версии. Ещё — версию Gradle wrapper и что
обновлять вместе: Kotlin и KSP, AGP и Gradle, Compose Multiplatform и Kotlin. Варианты
вроде `-jre`/`-android` сравниваются только между собой, alpha/beta/rc — с `--pre`.
Без аргументов — текущий проект, а если в нём нет каталога, все проекты. Ответы
репозиториев кешируются на 6 часов. Для Claude то же самое — инструмент `deps_outdated`.

## Состояние Mac для Claude

MCP-инструмент `mac_status` показывает Claude то же, что `mnrh ram`, `gradle`, `sim` и
`ports` (по запросу ещё `disk`): кто занял память, демоны Gradle и Kotlin, размеры кешей и
`build/`, запущенные симуляторы, занятые порты. Когда сборка падает по памяти или порт
занят, Claude может посмотреть сам. `free_memory` — это `mnrh ram clean`: останавливает
простаивающие демоны сборки и симуляторы (по желанию эмулятор Android). Claude Code
спрашивает разрешение перед каждым его вызовом, а читающие инструменты (`session_search`,
`session_read`, `mac_status`, `deps_outdated`) `mnrh claude setup` разрешает сразу в `permissions.allow`
в `~/.claude/settings.json`.

## Как работает перезапуск Claude Code

`mnrh claude setup` кладёт `~/.claude/commands/restart.md` и `forget.md` и регистрирует
MCP-сервер `mnrh` с инструментами `restart`, `forget`, `open_claude`, `session_search`,
`session_read`, `mac_status` и `free_memory` (scope user, во всех проектах). Дальше в любой сессии:

- `/restart` — сразу, без участия модели; `/restart --no-update` — без обновления;
- или попросить Claude «перезапустись» / «обновись» — он вызовет инструмент `restart`;
- `/forget` (или «забудь эту сессию» — инструмент `forget`) — разовая сессия: Claude
  закрывается, переписка удаляется с диска вместе с её строками в `history.jsonl`,
  `file-history` и `session-env`, экран и прокрутка терминала очищаются, и в той же папке
  открывается чистый Claude. В отличие
  от встроенного `/clear`, старое не остаётся в `/resume`. У самого Claude Code такого
  нет: `--no-session-persistence` работает только с `--print`.
- «открой Claude в kcalm» — инструмент `open_claude`: без проекта он возвращает в чат список
  проектов (ветка, последний коммит) и режимов, Claude спрашивает, что выбрать, и открывает
  новое окно того же терминала (Terminal или iTerm2) с `mnrh claude <проект> -k|-n`. Можно
  передать первый запрос и `--continue`. Remote Control (`/rc`) включается сразу
  (`--remote-control <проект>`, выключить — `remote_control: false`). В ответ — окно, tty, pid
  и ссылка claude.ai/code на сессию, чтобы продолжить с телефона или в браузере.

Что происходит: по дереву процессов находится свой `claude` и его запись в
`~/.claude/sessions/<pid>.json` (id сессии, папка, терминал). Отдельный отвязанный
процесс шлёт ему SIGTERM — Claude закрывается штатно, сессия уже на диске, — и в той же
вкладке выполняется `cd <папка> && { claude update; claude --resume <id>; }`.
Флаги запуска (`--model`, `--dangerously-skip-permissions`, …) и caffeinate сохраняются.

Как команда попадает обратно во вкладку:

- **хук zsh** (основной способ, любой терминал — Android Studio, VS Code, Terminal, iTerm2).
  `mnrh claude setup` добавляет в `~/.zshrc` строку с `share/mnrh/restart.zsh`. Перед
  закрытием Claude в `~/.cache/mnrh/restart/<tty>` кладётся задание, и zsh выполняет его
  перед следующим приглашением. Задания старше двух минут игнорируются. Работает во
  вкладках, открытых после установки;
- **AppleScript** — запасной вариант для Terminal и iTerm2, если хук в этой вкладке не
  загружен. Первый раз macOS может спросить разрешение на управление терминалом; это
  проверяется до закрытия, так что без разрешения Claude просто не закроется.

После запуска Claude показывает под строкой ввода, что произошло: «Claude Code перезапущен
(обновлён 2.1.278 → 2.1.280). Сессия «…» продолжается» или «прошлая сессия «…» удалена… Это
новая чистая сессия». Это хук `SessionStart` в `~/.claude/settings.json` (его ставит
`mnrh claude setup`): перед закрытием в `~/.cache/mnrh/notice/<id сессии>.json` кладётся
записка, хук её показывает и удаляет. Модели это не отправляется. `/forget` для этого
запускает новую сессию с заранее известным `--session-id`.

### Пустые сессии не копятся

После `/clear` Claude заводит новую сессию, и если сразу закрыть его, в `/resume` остаётся
«мусор»: внутри только запись о самой команде `/clear` и метаданные. `mnrh claude setup`
ставит хук `SessionEnd`: при закрытии своя сессия удаляется, если в ней нет ни одного
ответа Claude и ни одного твоего сообщения (служебные `/команды` не в счёт). Если Claude
закрыли крестиком и хук не успел, при следующем старте в этом же проекте хук `SessionStart`
в фоне убирает такие пустые сессии старше минуты, которые не открыты в других окнах.
Сессию с разговором это не трогает никогда, `!`-команды тоже считаются разговором.

### Строка состояния

`mnrh claude setup` ставит `statusLine` (если своей ещё нет). Две строки под вводом:

```
Opus 5.5 · контекст 64% · лимит 5 ч ▰▰▰▱▱ 55%, сброс в 13:30 · неделя 12%
master ↑3 ±5 · память 9.9/16 ГБ · swap 1.5 · Gradle 2 (3.1 ГБ) · файл сессии 467 МБ
```

Лимиты подписки показываются, когда Claude Code их отдаёт (Pro и Max, после первого ответа
в сессии): лимит 5 ч — со шкалой и временем сброса («в 13:30», «через 24 мин»), неделя —
со временем сброса от 50 %. Git: ветка, сколько коммитов не запушено (↑) и не забрано (↓), «не
запушена» для ветки без upstream, ± — изменённые файлы. Mac: занятая память и swap,
демоны Gradle и Kotlin с их памятью, запущенные симуляторы и эмулятор. Размер сессии —
от 50 МБ. Жёлтым и красным отмечено то, на что пора посмотреть. Данные о Mac кешируются
на 5 с, git на 3 с, строка обновляется ещё и раз в 10 с (`refreshInterval`). Своя строка
состояния, если она уже была, не заменяется.

### Защита: `mnrh claude guard`

Хук `PreToolUse` на Bash, Read, Edit, Write останавливает:

| Правило | Что |
|---|---|
| `force-push` | `git push --force` и `+ветка` в main, master, develop, release/* |
| `discard` | `git reset --hard`, `git clean -f`, `git checkout -- .`, `git restore`, когда есть что терять; `git stash drop/clear`, `git branch -D` |
| `rm` | `rm -r` за пределами проекта, `/tmp`, `/var/folders` и scratchpad сессии, сам проект, `~` и `/`; путь, который не раскрыть заранее |
| `release` | лейны fastlane с release, beta, upload, deploy, store, testflight, …; `gradle publish`; `gh release create`; `firebase deploy/appdistribution`; скрипты `*distribute*`, `*deploy*`, `*release*`, `*publish*` |
| `secrets` | чтение и правка `.env*` (кроме `.example` и т. п.), `*.p8`, `*.p12`, `*.jks`, `*.keystore`, приватных ключей SSH, `*service-account*.json`, `keystore.properties`, `.netrc`; `security find-*-password -w` |
| `sql` | `DROP TABLE/DATABASE`, `TRUNCATE`, `DELETE` без `WHERE` |
| `remote` | `ssh` с reboot, `systemctl stop/restart`, `docker compose down`, `rm -r` |
| `pipe-shell` | `curl … \| sh` |

В обычном режиме Claude Code просто спросит разрешение с объяснением. В режимах `auto` и
`--dangerously-skip-permissions` ответ «спросить» Claude Code превращает в «запретить» или
«разрешить», поэтому guard запрещает вызов и просит Claude спросить тебя: чтобы разрешить,
ты сам пишешь в чате четырёхзначный код из его вопроса (код привязан к команде и сессии,
модель не может написать его за тебя). `mnrh claude guard skip release` выключает правило,
`guard test '<команда>'` показывает решение, `guard log` — последние срабатывания.

### Уведомления, когда Claude ждёт тебя

`mnrh claude setup` ставит хуки `UserPromptSubmit`, `Stop` и `Notification` (асинхронные,
Claude их не ждёт). Уведомление macOS приходит, когда Claude:

- просит разрешение на инструмент или задаёт вопрос (в том числе от MCP-сервера);
- закончил ход, который шёл дольше 20 секунд (`mnrh claude notify after <сек>`);
- минуту ждёт ответа, а уведомления о готовом ответе не было.

Заголовок — проект и что случилось, ниже название сессии и начало ответа. Если ты и так
смотришь на эту вкладку (Terminal или iTerm2 впереди и выбрана именно она) или на окно IDE,
где идёт Claude, уведомления нет. Нажатие на уведомление открывает нужную вкладку в
Terminal и iTerm2 (по tty, как `/restart`), а в Android Studio, VS Code и т. п. — окно
приложения. Новое уведомление той же сессии заменяет старое, а после твоего следующего
запроса оно убирается из Центра уведомлений.

Показывает их маленькое приложение `~/Library/Application Support/mnrh/mnrh Notify.app`
(собирается из `share/mnrh/notify/main.swift`). В первый раз macOS спросит, можно ли ему
показывать уведомления, а при первом нажатии — можно ли ему управлять Terminal или iTerm2.
`mnrh claude notify test` — пробное уведомление, `notify off` / `on` — выключить и
включить, `notify sound off` — без звука.

Лог: `~/Library/Logs/mnrh-claude-restart.log`.

## Что проверяет `mnrh doctor`

- **Диск** — свободное место на томе данных.
- **Память** — swap, демоны сборки и сколько они держат, запущенные iOS-симуляторы.
- **Оболочка** — время запуска zsh, несуществующие каталоги и дубликаты в PATH
  (PATH берётся из чистого login-shell, как при открытии Терминала).
- **Ссылки** — битые симлинки в `~/.local/bin`, `~/.claude/skills` и Homebrew.
- **Claude Code** — права на `~/.claude.json` с токенами, MCP-серверы с несуществующей
  командой, записи на удалённые проекты.
- **Автозапуск** — службы launchd, чья программа удалена вместе с приложением.
- **Безопасность** — файрвол, FileVault, SIP, Time Machine, sudo без пароля, Gatekeeper,
  открытый доступ из сети (SSH, общий экран, удалённое управление, общие файлы — по
  слушающим портам, без sudo), автоустановка обновлений безопасности, системные расширения
  (и какие ждут разрешения), управление через MDM.
- **Аккумулятор** — циклы и остаточная ёмкость.

Код возврата 1, если найдены проблемы (не предупреждения) — удобно для скриптов.

## Как `mnrh disk` решает, что безопасно

Две группы. **Безопасное** пересоздаётся само, и только его удаляет `--apply`:
`build/` и `.gradle/` в проектах из папки проектов, Xcode DerivedData, кеши и логи старых
версий Android Studio и JetBrains, версии Gradle, которые не указаны ни в одном
`gradle-wrapper.properties`, build cache Gradle, кеши npm, pip, SwiftPM и CocoaPods,
`brew cleanup`, симуляторы без runtime.

**Стоит посмотреть** только показывается, с подсказкой команды: настройки старых
версий IDE, `node_modules`, кеш Chrome, Корзина, runtime iOS старше 60 дней без запуска,
символы старых версий iOS для отладки.

Из версий IDE всегда остаются самая новая и всё, что трогали за последние 7 дней.
Если ни в одном проекте не найден wrapper, версии Gradle не трогаются вовсе.
Без терминала `--apply` требует `-y` — подтвердить вопрос там нельзя.

Намеренно не трогаются: Xcode Archives (там dSYM для крашей), старые версии
Ruby-гемов (их чистка ломает `bundle exec` в проектах), содержимое Downloads.

## Что показывает `mnrh repos`

По каждому репозиторию в папке проектов: текущая ветка, сколько коммитов не отправлено
и насколько ветка отстаёт, изменённые и неотслеживаемые файлы, stash, и отдельной
строкой — другие ветки, у которых есть коммиты только локально.

✗ — есть коммиты, которых нет ни на одном remote: пропадут вместе с диском.
! — есть что отправить или закоммитить. ✓ — всё отправлено, дерево чистое.

Если у ветки не настроен upstream, но одноимённая ветка есть на remote, сравнение
идёт с ней, а в выводе подсказка `git branch -u`. Без `--fetch` данные на момент
последнего fetch — команда работает офлайн и за доли секунды.

## Почему `mnrh ram`, а не Stats или Activity Monitor

Stats показывает сжатую память одной полосой Compressed, без разбивки по процессам.
`ps` и RSS сжатую память не видят вовсе: простаивающий Gradle-демон с 5 ГБ
в RSS выглядит как 120 МБ. `mnrh ram` берёт у `top` полный объём процесса (MEM)
и его сжатую часть (CMPRS) и группирует вспомогательные процессы по приложению —
Chrome, Claude, iOS-симулятор идут одной строкой.

Сжатая часть учитывается в несжатом размере, поэтому сумма колонки больше,
чем «Занято»; утилита выводит текущий коэффициент сжатия.

`mnrh ram clean` останавливает то, что пересоздаётся само и держит больше всего:
демоны Gradle и Kotlin (занятые сборкой пропускает, `-f` снимает и их) и запущенные
iOS-симуляторы — `simctl shutdown` сохраняет их данные, входы в аккаунты остаются.
С `--emulator` ещё эмуляторы Android через `adb emu kill`, состояние уходит в Quick Boot;
по умолчанию эмулятор не трогается, потому что обычно он и нужен. `--daemons` и `--sim`
ограничивают выбор. Перед остановкой показывает список и спрашивает (`-y` без вопроса),
после — свободную память и swap до и после. Приложения не закрывает: в них могут быть
несохранённые данные, — только называет три самых тяжёлых.

## Зачем `mnrh fix scroll`

Scroll Reverser переворачивает прокрутку мыши, а тачпад оставляет как есть. Чтобы их
различать, он следит за касаниями тачпада, и после сна это слежение иногда отваливается:
вся прокрутка считается мышиной и переворачивается по обеим осям. Перезагрузка Mac
помогает только потому, что перезапускает и Scroll Reverser. `mnrh fix scroll` делает
именно это — без перезагрузки. Так же перезапускаются Mos, LinearMouse и
UnnaturalScrollWheels, если запущены они. Если ни одна не запущена, команда так и скажет.

## Как работает `mnrh scroll`

Замена Scroll Reverser: мышь прокручивается «классически», трекпад — «естественно».
macOS сама так не умеет, у неё одна настройка на всё.

Scroll Reverser решает, откуда пришла прокрутка, по касаниям пальцев: он отдельно слушает
жесты трекпада и считает прокрутку трекпадной, если за последние 0,2 секунды на трекпаде
были два пальца. После сна поток жестов иногда пропадает, и вся прокрутка становится
«мышиной» — отсюда перевёрнутый по обеим осям трекпад.

`mnrh scroll` смотрит на само событие: у каждого события прокрутки есть исходное
HID-событие с id устройства, а по id в IORegistry видно класс драйвера
(`AppleMultitouchTrackpadHIDEventDriver` у встроенного и Magic Trackpad). Жесты не нужны,
ломаться после сна нечему. На всякий случай после пробуждения перехват пересоздаётся, а
если macOS его отключит, он включается снова. Если id устройства получить не удалось,
колесо со щелчками считается мышью, плавная прокрутка не трогается.

Как устроено:

- `share/mnrh/scroll/main.swift` — помощник на Swift без зависимостей. `mnrh scroll on`
  собирает его `swiftc` в `~/Library/Application Support/mnrh/mnrh scroll.app`, подписывает
  ad-hoc и ставит в автозапуск (`~/Library/LaunchAgents/com.mnrh.scroll.plist`, launchd
  поднимет его и после падения). Пересобирается только при изменении исходника.
- Нужен доступ в «Универсальном доступе» — иначе macOS не даёт менять события. `on` открывает
  настройки и ждёт; после пересборки доступ надо включить заново, macOS видит новую программу.
- Настройки при первом `on` берутся из Scroll Reverser, дальше живут в `~/.config/mnrh/config`:
  `--mouse vh|v|h|off`, `--trackpad …`, `--step N` (строк за щелчок колеса, как Discrete
  scroll step в Scroll Reverser; 3 по умолчанию).
- `on` закрывает Scroll Reverser, иначе мышь перевернётся дважды. Автозапуск Scroll Reverser
  нужно снять в его настройках самому.
- `mnrh scroll test` 20 секунд показывает каждое событие: мышь или трекпад, что сделано.
- Лог: `~/Library/Logs/mnrh-scroll.log`, состояние: `~/.cache/mnrh/scroll.json`.
- `off` убирает из автозапуска, `remove` ещё удаляет помощника и сбрасывает доступ.

## Что показывает `mnrh sleep`

Разбирает `pmset -g assertions` по-человечески: кто держит Mac, насколько сильно
(только от простоя или даже с закрытой крышкой от сети — `caffeinate -s`, его ставит
`mnrh claude -k`) и зачем. caffeinate сопоставляется со своей программой: сессия Claude,
временная блокировка самого Claude Code (`-t 300`) или зависший — его программа уже
закрыта или он остался без родителя и срока. Звук, который держит Mac, показывается
с процессом-источником, в том числе из симулятора. Ниже — последние засыпания и
пробуждения с причиной из `pmset -g log`. `mnrh sleep fix` снимает только зависшие
caffeinate, живые блокировки не трогает.

## Как работает `mnrh ssh github`

`mnrh ssh github` и `mnrh ssh gitlab` — пошаговый мастер «Шаг N/7». Для GitLab ключ
добавляется через `glab` (мастер предложит войти через браузер), а без него — копируется в
буфер, открывается страница SSH Keys, и мастер ждёт, пока GitLab начнёт пускать по ключу.
Подпись в репозиториях GitLab — ключом GitLab-аккаунта: отдельный файл в `~/.config/git`
подключается через `includeIf "hasconfig:remote.*.url:git@gitlab.com:*/**"`, в остальных
репозиториях подписывает ключ GitHub.

Для GitHub: Сначала спрашивает аккаунт: «gh вошёл
как X, настраиваем его?»; если нет или `gh` никуда не вошёл — `gh auth login` через
браузер, и дальше настраивается тот аккаунт, в который вошёл. `mnrh ssh github <логин>`
берёт логин без вопроса. Если Sourcetree не установлен (ищется и по bundle id), шаг про
него пропадает: шагов шесть, Sourcetree нигде не упоминается. Каждый шаг проверяет, сделан ли он, и пропускается, поэтому
запускать можно сколько угодно раз. Запускать в Терминале: там мастер сам спросит права
у GitHub и подождёт, пока настроишь Sourcetree.

1. Выпускает `~/.ssh/github_<логин>_ed25519`. Пароль случайный и хранится только в Связке
   ключей (`ssh-add --apple-use-keychain`), вводить его не придётся. Затем ключ выгружается из
   агента и загружается обратно из Связки — если Связка пароль не приняла (из-под Claude Code
   или без Терминала macOS отвечает «User interaction is not allowed»), пароль снимается,
   чтобы ключ не стал бесполезным, а повторный запуск в Терминале поставит его снова.
   `--ask-passphrase` — задать пароль самому.
2. Ставит `com.mnrh.ssh-keychain` — при входе в систему ключи из Связки загружаются в агент.
   Без этого подпись коммита до первого `ssh` просила бы пароль.
3. Пишет в начало `~/.ssh/config` блок `Host github.com` с этим ключом и `IdentitiesOnly`
   (копия старого — `config.mnrh-backup`). Второй аккаунт получает свой хост:
   `github-<логин>` или `--alias`, клонировать им — `git clone git@github-<логин>:…`.
4. Добавляет ключ в GitHub через `gh` — для входа и для подписи. Нужны права
   `admin:public_key,admin:ssh_signing_key`; если их нет, мастер сам запускает
   `gh auth refresh` — он показывает код и открывает GitHub для подтверждения.
5. Включает подпись коммитов и тегов этим ключом (`gpg.format ssh`, `allowed_signers` для
   `git log --show-signature`). `--no-sign` — без подписи. Если в системе есть git старше
   2.34 (например, старый git-osx-installer в `/usr/local/bin`), подпись не включается:
   такой git не знает `gpg.format ssh` и перестаёт читать `~/.gitconfig` целиком.
   `mnrh doctor` тоже предупреждает, если старый git заслоняет системный.
6. Проверяет `ssh -T` — GitHub должен поздороваться нужным логином, — ставит `gh` на SSH и
   предлагает перевести `origin` репозиториев этого аккаунта в папке проектов с HTTPS на SSH.

7. Sourcetree: ключ в нём не выбирается — в окне аккаунта всегда написано `id_rsa.pub`, это
   просто надпись. Git в Sourcetree идёт через системный OpenSSH и берёт ключ из
   `~/.ssh/config` (шаг 3). Остаётся переключить аккаунт на Protocol SSH, чтобы новые клоны
   шли по SSH (менять только Protocol: после Connect Account Sourcetree считает правку новым
   аккаунтом и отказывается сохранять). Мастер открывает Sourcetree, ждёт Enter и проверяет это, читая его файл
   аккаунтов (`hostingservices_new.plist`). Сам файл не меняет — это внутренняя база Sourcetree.
   Заодно называет остальные аккаунты GitHub в Sourcetree, если они не нужны.
`mnrh ssh` без аргументов показывает ключи, загружены ли они и кем представляются GitHub.

## Как `mnrh uninstall` находит данные приложения

По идентификатору из `Info.plist`: в `~/Library` это папки и файлы с тем же именем —
`Caches`, `Preferences` (и `ByHost`), `Containers`, `Group Containers`, `Saved Application
State`, `HTTPStorages`, `WebKit`, `Cookies`, `Application Scripts`, `LaunchAgents`, — плюс
`Application Support`, `Caches` и `Logs` с именем самого приложения. Перед удалением
показывает всё с размерами и спрашивает. Всё уходит в Корзину через Finder, поэтому
работает «Вернуть». Приложение, поставленное через brew, удаляется `brew uninstall --cask`,
чтобы brew не считал его установленным. Системные приложения не трогаются, Xcode можно.

`--orphans` ищет в `~/Library` папки с именами-идентификаторами, которым не соответствует ни
одно установленное приложение (по Spotlight и по папкам приложений). Не считаются остатками:
Apple, консольные инструменты без `.app` (SwiftPM, Firebase, Google Updater, Gradle и т. п.) и
всё, что менялось за последние 7 дней, — раз меняется, значит, чем-то используется.
Показывается только то, что больше 1 МБ. `-n` — только показать.

## Что проверяет `mnrh net`

Для случая «Gradle sync или `pod install` не проходит»: маршрут и шлюз (с откликом — слабый
Wi-Fi видно сразу), VPN (и системный, и туннели сторонних приложений), DNS (какие серверы,
находятся ли и быстро ли имена репозиториев, нет ли их в `/etc/hosts`), прокси — системный,
PAC, переменные окружения и отдельно прокси Gradle: JVM системный прокси не видит, и если он
нужен, его надо прописать в `~/.gradle/gradle.properties`. Потом параллельно проверяет Gradle,
плагины Gradle, Maven Central, Google Maven, JitPack, CocoaPods CDN, GitHub, Apple и npm через
`curl` (системный Python 3.9 со старым LibreSSL зависает на части сайтов). Ошибку сертификата
объясняет отдельно. Код возврата 1, если что-то недоступно.

## Что показывает `mnrh login`

Три места, откуда macOS запускает сторонние программы: объекты входа (через System Events),
службы launchd пользователя (`~/Library/LaunchAgents`), для всех пользователей
(`/Library/LaunchAgents`) и от root (`/Library/LaunchDaemons`). По каждой: чья программа
(по пути к `.app`), кем подписана (`codesign`: Developer ID, Apple, adhoc, не подписано),
работает ли сейчас и когда запускается — при входе или по событию. ✗ — файла программы
уже нет, ! — подпись adhoc или нет подписи. Для `sh -c` видна сама команда.
`mnrh login off <имя>` убирает объект входа или свою службу (файл — в Корзину); для
системных служб печатает команду с sudo. Список фоновых объектов из Настроек (BTM)
читается только с sudo (`sfltool dumpbtm`), поэтому не показывается.

## Как работает `mnrh defaults`

Список из 19 настроек, которые обычно меняют под разработку: расширения и скрытые файлы
в Finder, строка пути и состояния, поиск в текущей папке, без `.DS_Store` на сетевых
дисках и флешках, быстрый повтор клавиш и повтор вместо меню с «ё» при зажатой клавише,
без «умных» кавычек, тире и автоисправления, развёрнутое окно сохранения, Dock без
задержки, рабочие столы не переставляются, скриншоты в `~/Pictures/Screenshots`, время
сборки в Xcode. Без аргументов показывает, что уже включено.

`apply` включает всё или выбранное по имени, перед этим запоминает старые значения в
`~/.config/mnrh/defaults-undo.plist` (только самые первые, повторный `apply` их не
перетирает) и перезапускает Finder, Dock или строку меню, если нужно. `undo` возвращает
всё как было, в том числе удаляет ключи, которых раньше не было.

`snap` сохраняет все домены `defaults` (около 650, пара секунд), `diff` сравнивает с
текущими и печатает готовые `defaults write`/`delete` — так находится ключ любой
галочки в Настройках, чтобы потом включать её скриптом. Служебные счётчики и время
последнего запуска прячутся.

## Как работает `mnrh input`

Помощник на Swift (`share/mnrh/input/main.swift`), собирается и ставится в автозапуск так же,
как `mnrh scroll` (общий код — `libexec/mnrh/lib/swiftagent.py`). Разрешений не требует:
смену активного приложения сообщает NSWorkspace, раскладку переключает Text Input Sources.

Когда приложение выходит на передний план, ему ставится раскладка по правилу, а если правила
нет — та, на которой его оставили в прошлый раз (`remember off` — не трогать). При первом `on`
английская назначается установленным средам разработки и терминалам: Android Studio, Xcode,
Terminal, iTerm2, VS Code, IntelliJ, Sourcetree и т. п. Правила — в `~/.config/mnrh/input.json`,
помощник перечитывает файл сам. `en`/`ru` — первая раскладка с этим языком, можно указать и
название или id раскладки.

## Зачем `mnrh audio keep-mic`

Когда Bluetooth-наушники (AirPods, Galaxy Buds) становятся микрофоном по умолчанию, macOS
переводит их в режим гарнитуры: звук в них становится моно и глухим, как в телефонном
звонке, — даже в музыке. `keep-mic on` ставит в автозапуск помощника на Swift
(`share/mnrh/audio/main.swift`), который следит за устройством ввода через CoreAudio и, если
им стали Bluetooth-наушники, возвращает встроенный микрофон. Звук он не читает, поэтому
разрешение на микрофон не нужно. Для звонка через микрофон наушников — `keep-mic off`.

## Новая команда

Положить файл в `libexec/mnrh/`: `имя.sh` запускается через bash, `имя.py` через
`/usr/bin/python3`, остальное — как исполняемый файл. Команда сразу доступна как
`mnrh имя`. Описание для `mnrh help` добавляется в функцию `describe` в `bin/mnrh`.
